# Part 3b-1: the NI keeps time

The sync box always runs, with a backup, and a session without it must still get in. That was the requester's
ruling of 2026-10-18. Until now a session whose sync box wrote no log, or lost the end of one, never got in. Part
3b-1 lets SpikeGLX's NI keep the session's time in those cases. It is the first of three branches under part 3b:
3b-2 is Intan by strobes, 3b-3 a partial sync box as the cross-check. An NI restart is 3c.
- **Spec:** `docs/superpowers/specs/2026-10-18-training-records-and-backup-clock-design.md`, amendments 39-51.
- **Plan:** `docs/superpowers/plans/2026-11-19-part-3b-1-ni-keeps-time.md`, seven tasks, built by subagents.
- **Branch:** `feat/part-3b-1`, from `plan/part-3b-1` (`1c3e87b`, the plan), from `spec/part-3b` (`8b3dfd4`), from
  `main` at `aae255c`.

## What was built

- **Task 1: synthetic sessions without the sync box** (`0bd8780`). The recipe can leave the sync box out. Its NI
  then carries no barcode and names its creation time, `fileCreateTime`, in `nidq.meta`. The `ci` and `eye`
  profiles are unchanged but for that meta line and the DONE marker's digest.
- **Task 2: the segment key is `segment_id`** (`2f2c224`). A segment is keyed by its file's path within its
  system's folder, in place of `segment_barcode`. One copy of the name, the same under every clock. Key order is
  no longer time order, so anything that needs time order sorts by `start_s`.
- **Task 3: which clock keeps time** (`1946ec0`, `741e239`, `74d2f7b`). Two rules, decided when a stage first asks
  and recorded in `timebase.SessionClock`:
  - Rule 1, the sync box keeps time (amendment 42): it has a log, was not landed without, and either its log
    reaches the end of the rig's last run or it restarted within the session. A gap mid-session, or a log
    starting late, keeps the sync box.
  - Rule 2, the NI keeps time: otherwise, where its codes hold every run.
  - The NI is decoded outside the clock's transaction (amendment 43), and the cheap choice goes first.
  - **`ClockRefusal`**: when no clock can be chosen, the reason is recorded, keyed by session, with a digest of
    what the choice read and of the rules' version (`clock.py::CHOICE_RULES`, bumped whenever `choose` changes).
    A later pass reuses the reason until an input or the rules change, and the events stage reports it on each
    pass. A clock is chosen again only when the digest moves.
  - **`wlpp clocks backfill`** gives the sync box's clock to every session timed before its clock was recorded
    (amendment 48). It is run once.
- **Task 4: SpikeGLX on the NI's clock** (`407ed2f`, `2c167a4`). Devices on the NI's clock are placed by the NI.
  A device with no way onto it is unfittable (amendment 51). **NI code words are timed at the strobe's rising
  edge**, their value read at the far edge, as the sync box's are and as wl-sync stamps them. A second NI file
  makes the session NI_RESTARTED.
- **Task 5: tier N** (`31742dd`). The NI kept time, its codes hold every run, and nothing failed. Under the NI,
  `n_barcodes_emitted`, `event_code_agreement` and `trial_count_agreement` are null, since there is no barcode
  stream to compare. The listing's `tier` enum gains `N`.
- **Task 6: t = 0 and the NWB file** (`15be2ab`, `1d3c18b`). An NI-timed file says the NI kept time
  (`quality.clock = "nidq"`). t = 0's wall-clock time comes from the rig's clock fitted to the recording
  (`rig_clock`), else the first NI file's `fileCreateTime` (`nidq_meta`), else the manifest. `fileCreateTime`
  has no zone, so it is read in the lab NI machine's zone, given by **`--nidq-timezone` on the daemon and on
  `wlpp nwb build`**, through one shared helper, so a file rebuilt by hand places t = 0 as the daemon's did.
- **Task 7: these records.** wl.works' amendment, the segment-key text in `lab-host-protocol.md` and
  `pending-wl-works-amendments.md` corrected, and `ListedRun`'s docstring (and so its schema description).

## Rulings

Each with what it costs if wrong. The ledger, `.superpowers/sdd/2026-11-19-part-3b-1-ni-keeps-time/progress.md`,
holds the full wording.
1. **Pre-flight, Task 3:** `clock_for` inside a transaction with no recorded row still chooses and records the
   sync box when rule 1 holds, and raises `NoClock` only when choosing would need the NI decoded. Amendment 43
   forbids decoding in a transaction, not choosing the sync box there. Cost if wrong: a stage asked inside a
   transaction for an NI session fails where a daemon pass would have recorded the clock first. The daemon always
   does, so only direct test and CLI callers meet it.
2. **Task 3:** `nidq_files` orders by SpikeGLX's gate and then trigger index, parsed as integers from
   `_g<N>_t<M>.nidq.bin`; a name without them first, then by name. Text order puts g10 before g2, and the
   segment key (a path) is unfit for time order. Cost if wrong: under 3c a restart session with an odd naming
   takes the wrong file as t = 0 (it is tier D until 3c anyway).
3. **Superseded by ruling 8; read ruling 8 for the rule as built.** The text below is kept as it was ruled.
   **Task 3, a plan defect:** the plan's rule 1 ("its codes hold every run, or it restarted") was narrower than
   amendment 42, which binds. Rule 1 holds when the sync box has a log, was not landed without, and either its
   codes hold the session's last run or it restarted within the session. A gap mid-session, or a log starting
   late, keeps the sync box, because under the NI every other device is tier D (amendment 51). Cost if wrong: a
   session whose sync box lost a middle run keeps the sync box, and that run is handled by today's loss machinery
   instead of NI-timed.
4. **Task 3:** inside a transaction, a session with no NI to decode (SpikeGLX landed without, or no NI file) gets

6. **Task 3:** a sync box log that decodes no barcode hands the session to the NI, since such a log cannot place
   anything on its clock. Cost if wrong: a log with codes but no barcodes would have held runs but timed nothing

7. **Task 3, the review's I1:** record the refusal in `timebase.ClockRefusal` (session key; reason `varchar(255)`;
   `inputs` `char(64)`, a digest of the names, sizes and mtimes of the sync box log, every NI file and the rig's
   record files, plus the session's `LandedWithout` rows, and, since the final review's I2, the version of the
   rules that read them, `CHOICE_RULES`). Written when no clock can be chosen, deleted when one is. An unreadable
   NI becomes a recorded reason. Amendment 37 requires the reason on each pass and the digest keeps amendment
   43's "cheap first" true on every pass. Cost if wrong: a refusal is stale if an input changes without changing
   size or mtime (a same-size rewrite within the same second), or if `choose` changes and `CHOICE_RULES` is not
   bumped; a refusal recorded under rules since changed, with the constant bumped, is decided again. `wlpp clocks
   retry` is not added.
8. **Task 3, correcting ruling 3:** rule 1's last-run test is "the log reaches the end of the rig's last run", not

   the sync box. Amendment 42's text is "its log ends before the session's last run does". Since the final
   review's I1, a log that decodes `SESSION_END`, or the last run's `RUN_END`, reaches the end whatever was lost
   or failed its checksum before it; the trial line decides only when neither is decoded. Its reason names what
   it reached, then the first thing its codes lack (the final review's M3). Cost if wrong: a session whose sync
   box lost trials in its last run keeps the sync box.
9. **Task 4:** TimingProvenance for an NI session with nothing failed is Task 5's (tier N, the nulls). Task 4

10. **Task 4:** the second NI file in the restart test is the synth's own restart path,
    `<session_id>_g1_t0.nidq.bin` beside the first, not in a `_g1` folder. Cost if wrong: none.
11. **Task 4:** an NI code word's time is its strobe pulse's rising edge, its value read at the far edge. The rig
    asserts data and strobe together at T1's start (design 4.2.1); wl-sync stamps W at the rising edge plus

12. **Task 4:** a `no_recording` row under the NI says `time_source='barcode'`. Accepted for now, with a minor

13. **Task 4:** SpikeGLX under the NI has `n_barcodes_matched=0`. The NI's clock has no barcode reference to

## The review

Every task had its own review and fix loop. The whole branch (`aae255c..8575044`) was then reviewed on Opus,
pointed at the plan's Review Focus, the rulings above and the deferred minors. It found no Critical, two
Important and eight Minor findings.
- **Important:** I1, a lost or corrupt word in the last trial took a healthy sync box off the clock (ruling 8);
  I2, a recorded refusal never saw a change to the rules that made it (ruling 7).
- **Minor, fixed by effect:** M1, "barcode" texts in an NI-timed file and `file_path`'s folder; M2, the
  end-to-end test's error filter; M3, the reaching reason; M4, wl.works' reference document; M5, this
  handoff's Deploy section; and Task 7's minor (ruling 3).
- **Minor, deferred:** M6, M7 and M8, listed below.

One fix wave (`3114a0a..701eae2`) fixed both Important findings and the six Minor ones, each with a test that
failed first. A scoped re-review (Sonnet) found every finding addressed and nothing new broken.

The fix wave's I1 opens one narrow case, ruled and carried to 3b-3 (below). A lost escape word turns a payload
word into a simple code, so a 2 reads as `SESSION_END` and a 4 as `RUN_END`. If that happens in a log that truly
stops inside the last run, the sync box is kept. The session is then timed by the sync box with its losses
handled, as on `main`. Both faults must happen together, and the reverse error, one corrupt last-trial word
refusing a healthy sync box, is far commoner.

The final review agreed with rulings 1, 3-6 and 9-17. It disagreed with 7 and with 8 as built, and both are now
fixed (I2, I1). It held a reservation on 2: the name tie-break is not time order (M8, for 3c).

## Carried to later parts

- **To 3b-3:** `TimingProvenance`'s `fails_the_timing_check` compares a present sync box's losses (in its own
  time) against runs on the NI's time. Harmless while such a session is tier D.
- **To 3b-3:** `TimingProvenance` keeps off the NI's codes only because the sync box is never fitted under the NI
  (`timebase.py:787-791`). Make `syncbox_fitted` require `clock.source == "syncbox"`.
- **To 3b-3:** a partial sync box log can cross-check the NI; 3b-3 matches its barcodes (ruling 13).
- **To 3b-3:** `holding.unreached_end` counts `SESSION_END` or the last run's `RUN_END` wherever it is decoded.
  After a lost escape word, a payload word of 2 or 4 reads as one of them, and keeps a sync box that truly
  stopped inside the last run (the review, above). Count an end code only when it is the log's last code, or
  comes last but for `BLOCK_END` and `RUN_END`.
- **To 3c:** an NI restart (a second NI file) is `NI_RESTARTED`, tier D, until 3c. The restart's `fileCreateTime`
  and the "first NI file" are chosen by time, never by key order.

## Deploy

- **Purge serv's development database before deploy.** Enums and nullability changed (`tier` gains N,
  `reference_source` gains two values, `ClockRefusal` is new), and development databases are rebuilt, never
  migrated.
- **`wlpp clocks backfill` applies only to a database that is kept, or one restored from a dump made before
  3b-1** (amendment 48): run it once there, so a session timed before its clock was recorded gets the sync box's.
  After the purge above it finds nothing to do, since no session is timed yet.
- **Pass `--nidq-timezone <the lab NI machine's IANA zone>` to the daemon.** The lab must name the zone: SpikeGLX
  writes `fileCreateTime` in the NI machine's local time with no zone, and nothing here assumes which. Without
  it, the NI's file-creation source is skipped, and an NI-timed file's t = 0 comes from the rig's clock or, failing
  that, the manifest. `wlpp nwb build` takes the same option.
