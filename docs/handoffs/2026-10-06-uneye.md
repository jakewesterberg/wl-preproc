## 1. What was built

- **The copy:** `wl_preproc/eye/vendor/uneye/` holds upstream's package at `f97ca88` and its five
  two-class networks.
  - `classifier.py`'s one import line is changed.
  - `PROVENANCE.md` records the source, the absent licence, the citation and the change.
  - `test_uneye_copy.py` holds every file to upstream's sha256.
- **The wrapper:** `wl_preproc/eye/detect/uneye.py`.
  - `UneyeParams`: the network, a 6 ms minimum, a 20 ms merge gap. Default `weights_dataset3`.
  - `detect_uneye` runs the network on each usable stretch of 25 samples or more, always on the
    CPU.
  - Each saccade carries the network's mean saccade probability as its reliability.
- **Registered as `uneye`,** vocabulary `{saccade}`. Its conjunction floor is 3 samples at the
  rig's rate. Importing the registry still does not import torch.
- **BMD's kernels run on numba's own thread pool** (amendment 6), so torch's OpenMP runtime is
  the only one in a process. With a second one, U'n'Eye's first convolution waits forever: the
  proof's full suite on the Anaconda-based 3.13 venv hung seven hours on it. In the daemon that
  would be a stuck session with no error. BMD's results cannot change, and its tests against its
  authors' C++ pass on both interpreters.
- **Dependencies:**
  - `pyproject.toml`'s new `uneye` extra (torch, scikit-image, scikit-learn, matplotlib), plus
    package data for the networks;
  - `wl.yaml` entries for each, with no `where` (amendment 2), and `uneye` pinned at the commit;
  - CI installs CPU torch, then `.[dev,uneye]`, on both interpreters.
- **The local environments:**
  - the 3.11 venv gained scikit-image;
  - the 3.13 venv (`~/.cache/wl-preproc-venv313`) gained CPU torch 2.14.1, scikit-image and
    scikit-learn.

## 2. What it measured

- **Speed:** 1.4 s on the CPU for a 1.18M-sample trace, so no GPU is needed and there is no
  `slow` marker.
- **The default network's choice** rests on these results (amendment 1), measured at upstream's 1 ms
  merge gap. At the 20 ms default, `weights_dataset3` finds 533 of 541 and 541 of 548.

| Network at 500 Hz | Synthetic, 5–15 deg found | Andersson, coded saccades found |
|---|---|---|
| `weights_dataset3` (default) | 120 of 120 | 98% (530 of 541; 538 of 548) |
| `weights_1+2+3` | 57 of 120 | 71% (386; 390) |

- **The merge gap** rests on these results (amendment 7, which has the full table), per coder,
  on their coded saccades of 6 deg or more:

| Merge gap | Split into several | Stored over twice the coded duration | Median duration over coded |
|---|---|---|---|
| 1 ms (upstream) | 44 of 177; 48 of 169 | 5; 2 | 0.83; 0.80 |
| 20 ms (default) | 3; 3 | 31; 25 | 1.24; 1.18 |

- **The defaults' costs:**
  - More extra detections on the Andersson data than `weights_1+2+3`: 583 and 584, against 412
    and 409 (886 and 872 at 1 ms).
  - Durations run long, mostly by taking in the glissade.
  - A run merged across a gap can carry a reliability under 0.5: 8 of 1,112.
  - On `stepped_session` it reported one 0.10 deg fixational wobble beside the three planted
    steps, which it found within 1 sample of each (amendment 4).
- **Found only by the review:** counting any overlap, as amendment 1's evidence did, cannot see
  a split. The validation test now counts splits too.
- **The networks were trained on video trackers, not the lab's dual-Purkinje tracker.** U'n'Eye's
  rows are provisional until a network is fine-tuned on hand-labelled lab data, after January.

## 6. The review

A fresh reviewer read the whole branch. It found no Critical issue and one Important one.
- **Important, fixed:** the default split large saccades (amendment 7). The requester chose a
  20 ms merge gap, then confirmed it once shown the duration cost, which the reviewer's own
  table had understated.
- **Verified by the review:**
  - the copy is byte-identical to upstream except the one line;
  - a built wheel ships the networks;
  - nothing torch-related loads when the registry is imported;
  - every reader of `reliability` is safe with a third meaning;
  - nothing else counts six detectors;
  - `wl.yaml` and amendment 2's reading of wl-orchestrator hold.

**Deferred minors,** for a later branch:
1. Some citations point to the wrong place:
   - `UneyeParams` and `test_uneye_validation.py` cite the spec's section 3 for what amendments 1
     and 7 now decide;
   - `test_detect_populate.py` cites section 5 for the wobble allowance, which is amendment 4.
   - (The module docstring's "70%", also listed, was corrected in the fix.)
2. The spec's body (§3's default, §4's `where: serv`, §5's "no validation test") has no
   "superseded by amendment N" pointer.
3. A detection machine installed without the `uneye` extra parks U'n'Eye's job, and every NWB
   then waits on it. No recorded install omits the extra. A loud start-up check in the daemon is
   the fix if wanted.
4. The threading-layer setting sits in `bmd.py`, so it covers a process only once `bmd` is
   imported. `wl_preproc/eye/detect/__init__.py` would also cover a direct import of `uneye`, in
   a notebook.

## 7. The deferred minors, fixed

**Branch:** `fix/uneye-minors`. The requester chose this work on 2026-10-07 and approved its
design the same day.

- **Minor 3, a host without U'n'Eye's libraries:**
  - `wlpp daemon` refuses a pass and `wlpp doctor` fails `detector libraries`, each naming the
    install that fixes it.
  - Each `Detector` carries `unavailable`. U'n'Eye's imports its own code as its jobs do, so a
    broken install fails as a missing one does.
  - The approved design looked the libraries up without importing them. The package's network
    guardrail forbids that (`importlib`, `sys.modules`: `tests/test_cli_guardrails.py`), and the
    requester chose the import.
  - torch therefore loads in the daemon and in doctor, about 2 s. The registry itself still
    imports without it.
- **Minor 4, the threading setting:** it stays in `bmd.py`. Moving it would have added numba's
  0.5 s import to every CLI path through `schema/detect.py`. Instead U'n'Eye refuses to start,
  with an error, where numba chose OpenMP before it ran. That is tested against real numba where
  OpenMP loads (this machine's 3.13 venv).
- **Minors 1 and 2:** the citations name amendments 1, 3, 4 and 7, and each superseded spec
  passage names its amendment.

**The branch's own review** found one Critical, fixed: the guardrail failure above. Minors deferred:
- **`bmd.py`'s setting is undone if a `NUMBA_*` environment variable changes after `bmd` is
  imported,** since numba re-reads its environment when it compiles. Nothing in the repository
  does that. Setting `os.environ["NUMBA_THREADING_LAYER"]` as well would close it.
- **The guard cannot see numba choosing OpenMP after torch has loaded.** The review measured a
  crash (SIGSEGV), not a hang. Its docstring says so.
- **The doctor tests open a real database connection,** which is safe in CI.
